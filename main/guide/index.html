    User guide¶

    This guide collects the recommendations, the patterns and the troubleshooting tips for using minevent. The quickstart explains the API step by step, and the architecture page lists the guarantees of the library.

    Events¶

    An event is a case-sensitive str. Any other type raises a TypeError.

    • Name the event after what happened, in the past tense: epoch_end, checkpoint_saved, not event1 or done.
    • Pick one convention for the whole project, for example snake_case (batch_end) or a namespace (training.batch.end). Names are only strings, so minevent has no notion of hierarchy.
    • Define the names in one place (constants or an Enum with str values) to avoid typos: the events "epoch_end" and "epoch-end" are different, and triggering an event without handler does nothing.

    Event handlers¶

    Keep handlers focused¶

    One handler does one thing (log, save, update a progress bar). Handlers of an event run in the order they were registered, so register them in the order they must run.

    Pass the data as a payload¶

    The keyword arguments of trigger_event are passed to every handler:

    >>> from minevent import EventHandler, EventManager
>>> def log_epoch(epoch: int, loss: float) -> None:
...     print(f"epoch {epoch}: {loss}")
>>> manager = EventManager()
>>> _ = manager.add_event_handler("epoch_end", EventHandler(log_epoch))
>>> manager.trigger_event("epoch_end", epoch=3, loss=0.5)
epoch 3: 0.5

    Every handler of the event receives the whole payload, and a handler that does not accept a key raises a TypeError. Use filter_payload=True to give each handler only the keys of its signature, so handlers with different needs can share an event:

    >>> from minevent import EventHandler, EventManager
>>> def log_epoch(epoch: int) -> None:
...     print(f"epoch {epoch}")
>>> manager = EventManager()
>>> _ = manager.add_event_handler("epoch_end", EventHandler(log_epoch, filter_payload=True))
>>> manager.trigger_event("epoch_end", epoch=3, loss=0.5)
epoch 3

    handler_args and handler_kwargs are given to the handler before the payload. A key that is in both handler_kwargs and the payload raises a TypeError.

    Handle the exceptions¶

    Handlers run fail-fast: if a handler raises, the exception reaches the caller of trigger_event and the next handlers of the event do not run. The exception is the original one, with a note that names the event and the function of the handler (never its arguments):

    >>> from minevent import EventHandler, EventManager
>>> def fail() -> None:
...     raise ValueError("boom")
>>> manager = EventManager()
>>> _ = manager.add_event_handler("my_event", EventHandler(fail))
>>> try:
...     manager.trigger_event("my_event")
... except ValueError as exc:
...     print(exc.__notes__[0])
raised by fail while handling the event 'my_event'

    If the failure of a handler must not stop the training, catch the exception in the handler. There is no option to collect the errors of all the handlers (see the non-goals in the architecture page).

    Async handlers¶

    trigger_event is synchronous. A handler that returns an awaitable (a coroutine function) raises a TypeError there, instead of silently dropping the coroutine. Use atrigger_event to await the handlers, one after the other, in the registration order. Synchronous handlers can be mixed with coroutine handlers, and they block the event loop while they run.

    Conditions¶

    A condition is a function without argument that returns a boolean. It is called each time the event is triggered, before the handler, and the handler runs only if it returns True:

    from minevent import EventHandler, PeriodicCondition

# Save a checkpoint every 10 epochs, and log every 100 batches
manager.add_event_handler(
    "epoch_end", EventHandler(save_checkpoint, condition=PeriodicCondition(freq=10))
)
manager.add_event_handler(
    "batch_end", EventHandler(log_batch, condition=PeriodicCondition(freq=100))
)

# Any function works as a condition
manager.add_event_handler("epoch_end", EventHandler(notify, condition=lambda: is_main_process))
    • PeriodicCondition and AfterNCondition keep a counter. Do not share one instance between two handlers: they would advance the same counter. Create one per handler.
    • To combine conditions, write a function. lambda: a() and b() skips b when a is False; lambda: all([a(), b()]) evaluates both, so stateful conditions advance together.
    • A stateful condition is not protected by a lock: call it from one thread.

    The event manager¶

    Create it in one place¶

    Create the manager once and pass it where it is needed. minevent has no global manager on purpose: it keeps the tests independent and makes the ownership clear.

    def main():
    manager = EventManager()
    setup_handlers(manager)
    Trainer(manager).train()


def setup_handlers(manager: EventManager) -> None:
    manager.add_event_handler("epoch_end", EventHandler(save_checkpoint))
    manager.add_event_handler("training_end", EventHandler(log_summary))

    Keep the subscription¶

    add_event_handler returns a Subscription, the registration of the handler. It is the only way to identify a registration: event handlers are compared by identity, so a new EventHandler built with the same arguments is a different object.

    >>> from minevent import EventHandler, EventManager
>>> manager = EventManager()
>>> subscription = manager.add_event_handler("my_event", EventHandler(print))
>>> subscription.active
True
>>> subscription.remove()
True
>>> subscription.remove()
False
    • remove() removes that registration only, once. It returns False if the registration is already gone (removed, or cleared by clear_event or reset, or consumed by once=True).
    • with manager.add_event_handler(...): removes the registration when the block exits, which is convenient for a profiler or a progress bar that lives for one phase of the program.
    • manager.get_subscriptions(event) lists the registrations of an event if you did not keep them, and subscription.event_handler gives the handler.
    • @manager.on("event") registers a function as a handler and returns it unchanged.
    • once=True removes the registration at the next trigger of the event, even if the condition of the handler is False. To wait for the first time the condition is True, see the quickstart.

    Avoid duplicates¶

    Registering the same handler twice runs it twice. To register it once, look at the registrations:

    if not any(sub.event_handler is handler for sub in manager.get_subscriptions("my_event")):
    manager.add_event_handler("my_event", handler)

    Clean up¶

    A registered handler lives as long as the manager: EventHandler(obj.method) keeps obj alive, and so do handler_args and closures. minevent uses no weak reference. Remove the subscriptions of the objects you no longer need, use a with block, or call clear_event / reset:

    try:
    trainer.train(manager)
finally:
    manager.reset()

    Integration patterns¶

    Training loop¶

    class Trainer:
    def __init__(self, model, manager: EventManager) -> None:
        self.model = model
        self.manager = manager

    def train(self, epochs: int, loader) -> None:
        self.manager.trigger_event("training_start")
        for epoch in range(epochs):
            self.manager.trigger_event("epoch_start", epoch=epoch)
            for batch in loader:
                loss = self.step(batch)
                self.manager.trigger_event("batch_end", epoch=epoch, loss=loss)
            self.manager.trigger_event("epoch_end", epoch=epoch)
        self.manager.trigger_event("training_end")

    Plugins¶

    A plugin registers its own handlers, and keeps the subscriptions to unregister them:

    class LoggingPlugin:
    def setup(self, manager: EventManager) -> None:
        self.subscription = manager.add_event_handler(
            "training_end", EventHandler(self.log_training_complete)
        )

    def teardown(self) -> None:
        self.subscription.remove()

    def log_training_complete(self) -> None:
        print("Training completed!")

    Custom handlers and conditions¶

    Implement BaseEventHandler.handle(self, /, **payload) for a handler with its own state (override ahandle for a coroutine). A condition is any class with a __call__(self) -> bool method.

    Testing¶

    Test a handler without a manager, and the wiring with a mock:

    from unittest.mock import Mock


def test_epoch_end_calls_handler():
    manager = EventManager()
    mock = Mock()
    manager.add_event_handler("epoch_end", EventHandler(mock))
    manager.trigger_event("epoch_end", epoch=1)
    mock.assert_called_once_with(epoch=1)


def test_handler_directly():
    EventHandler(print, handler_args=("test",)).handle()

    Use a new EventManager in each test, and manager.reset() if the manager is shared.

    Performance¶

    The cost of trigger_event is the cost of the handlers: about 0.7 µs for a manager with one trivial handler, and about 0.4 µs for each additional handler on a laptop. A condition avoids the work of an expensive handler (PeriodicCondition). To find a slow handler, time it or enable the logging.

    A handler that is slow blocks the caller. Hand the work to an executor in the handler if the caller must not wait.

    Pitfalls¶

    • A handler that retriggers its own event recurses until RecursionError. Use a different event or a flag.
    • A handler removed during a trigger still runs in that trigger. The registrations that exist when the trigger starts are run. Handlers added during a trigger run at the next trigger. A once registration removed by an earlier handler of the same trigger does not run.
    • The payload is shared: all handlers get the same objects. A handler that mutates a payload object is seen by the next handlers.
    • Threads: the registry is thread-safe, the handlers run in the thread that triggers the event, concurrently if several threads trigger it. A handler that shares state must protect it.

    Troubleshooting¶

    My handler does not run¶

    1. The handler is registered for that event: manager.get_subscriptions("my_event").
    2. The event name matches exactly (case-sensitive).
    3. The condition returns True (a PeriodicCondition(freq=5) skips four calls out of five).
    4. It was not registered with once=True and already consumed: subscription.active is False.
    5. A handler of the same event ahead of it raised: the next handlers are skipped.

    TypeError: ... got an unexpected keyword argument¶

    The payload is given to every handler. Accept **kwargs or use filter_payload=True.

    TypeError: ... returned an awaitable; use ahandle or atrigger_event¶

    The handler is a coroutine function. Call await manager.atrigger_event(...).

    subscription.remove() returns False¶

    The registration is already removed. This is not an error: remove() is idempotent.

    Debug¶

    • print(manager) shows the number of handlers of each event, and manager.get_subscriptions(e) the registrations.
    • Enable the minevent logger to see the registrations and the triggers:
    import logging

logging.basicConfig(level=logging.DEBUG)
logging.getLogger("minevent").setLevel(logging.DEBUG)
    • Register a handler that prints the payload while you investigate:
    manager.add_event_handler("batch_end", EventHandler(lambda **payload: print(payload)))
