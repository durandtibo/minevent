    Main classes and functions¶

    The names that minevent exports. Import them from the package, for example from minevent import EventManager.

    minevent ¶

    Contain the main features of the minevent package.

    minevent is a minimal event system with three concepts: an event (a case-sensitive string), a handler (Handler) and an event manager (EventManager) that registers the handlers and triggers the events. A registration returns a Subscription, the handlers and the conditions that take a parameter receive the payload of a trigger in a read-only Context, and a Condition, such as PeriodicCondition, controls when a handler runs.

    The package has no dependency, and __version__ is the version of the installed package.

    Example 
    >>> from minevent import EventManager
>>> manager = EventManager()
>>> _ = manager.add_event_handler("epoch_end", lambda context: print(f"epoch {context['epoch']}"))
>>> manager.trigger_event("epoch_end", {"epoch": 3})
epoch 3

    minevent.Context ¶

    Bases: Mapping[str, Any]

    Implement a read-only mapping of the payload of a trigger.

    The data is copied at construction into a private dict, whose keys are checked, and a context has no method that changes it (no __setitem__, update or pop), so neither the code that built the context nor a handler can change what the next handler sees. The values themselves are not copied: a mutable value stays mutable. A context can be copied, deep-copied and pickled (with the protocol 2 or higher, like the default one) if its values can.

    The values are typed Any: a type checker lets a handler use a value without a cast, and it does not check how the value is used.

    context[key] reads a required value and raises a KeyError if it is missing. Its message lists at most 20 of the keys and shortens the long ones. context.get(key, default) reads an optional value. get and key in context do not build the message of that error, so they cost the same for a present key and a missing one, whatever the number of keys. len, iteration, keys, items, values and == behave like those of any collections.abc.Mapping, so dict(context) is a valid **kwargs. A context is equal to a mapping that has the same items, and it is not hashable. The class is final: a type checker reports a subclass.

    Parameters:

    Name Type Description Default
    data Mapping[str, object] | None

    The mapping to copy, or None for an empty context. Default is None.

    		 None

    Raises:

    Type Description
    TypeError

    if data is neither None nor a mapping, or if a key of data is not a str.
    Example 
    >>> from minevent import Context
>>> context = Context({"epoch": 3, "loss": 0.5})
>>> context["epoch"]
3
>>> context.get("lr", 0.1)
0.1
>>> "loss" in context
True
>>> len(context)
2
>>> context
Context({'epoch': 3, 'loss': 0.5})
>>> import copy
>>> copy.deepcopy(context)
Context({'epoch': 3, 'loss': 0.5})

    minevent.EventManager ¶

    Implement an event manager.

    add_event_handler registers a handler to an event, a case-sensitive string, and returns the Subscription that removes it. The on decorator registers the function that it decorates. trigger_event and atrigger_event run the handlers of an event in the order they were added, and clear_event and reset remove registrations. events, get_subscriptions and event in manager read the registry, which is thread-safe, and repr shows the number of handlers of each event. A manager is always truthy and has no length. Copying or pickling it raises a TypeError. The guarantees and the limits are in the "How It Works" page of the documentation, and the reasons in its "Design Choices" page.

    Example 
    >>> from minevent import EventManager
>>> manager = EventManager()
>>> _ = manager.add_event_handler("my_event", lambda: print("Hello!"))
>>> manager.trigger_event("my_event")
Hello!
>>> manager
EventManager(events={'my_event': 1})

    minevent.EventManager.add_event_handler ¶

    add_event_handler(
    event: str,
    handler: Handler,
    *,
    once: bool = False,
    condition: Condition | None = None,
) -> Subscription

    Add a handler to an event.

    Each trigger of the event calls the handler after the handlers added before it, as handler(), or as handler(context) with the read-only Context of the trigger if it has one parameter without default. minevent.calls.adapt_call states the whole rule. Use a function, a lambda or a functools.partial to give other arguments.

    Parameters:

    Name Type Description Default
    event str

    The event name (case-sensitive string).

    		 required
    handler Handler

    The callable to attach to the event (Handler).

    		 required
    once bool

    If True, the registration is removed just before the first call of the handler, so it runs at most once, even when several threads trigger the event. A condition that is False does not consume it. Default is False.

    		 False
    condition Condition | None

    A synchronous function that returns a boolean, called like a handler before it: the handler runs only if the result is true. A stateful condition, such as PeriodicCondition, must not be shared between registrations. If None, the handler always runs. Default is None.

    		 None

    Returns:

    Type Description
    Subscription

    A subscription whose remove method removes this registration only.

    Raises:

    Type Description
    TypeError

    if event is not a string, if handler is not callable, if condition is neither None nor callable, if once is not a bool, if handler or condition is a generator function, needs another argument than the context, or has a signature that cannot be inspected, or if condition is a coroutine function. A callable object is judged by its __call__. The manager is unchanged.
    Example 
    >>> from minevent import EventManager, PeriodicCondition
>>> manager = EventManager()
>>> _ = manager.add_event_handler(
...     "epoch_end",
...     lambda context: print(f"epoch {context['epoch']}"),
...     condition=PeriodicCondition(freq=2),
... )
>>> _ = manager.add_event_handler("epoch_end", lambda: print("first"), once=True)
>>> manager.trigger_event("epoch_end", {"epoch": 0})
epoch 0
first
>>> manager.trigger_event("epoch_end", {"epoch": 1})
>>> manager.trigger_event("epoch_end", {"epoch": 2})
epoch 2

    minevent.EventManager.atrigger_event async ¶

    atrigger_event(
    event: str, context: Mapping[str, object] | None = None
) -> None

    Run the handlers of an event, awaiting the coroutine handlers.

    It behaves like trigger_event, but the awaitable that a handler returns is awaited before the next handler. A synchronous handler blocks the event loop while it runs. The registrations and the context are read when the coroutine starts to run, not when it is created (see the "Limits" of the "How It Works" page of the documentation).

    Parameters:

    Name Type Description Default
    event str

    The event name (case-sensitive string) to trigger.

    		 required
    context Mapping[str, object] | None

    The data of the trigger, as in trigger_event. Default is None.

    		 None

    Raises:

    Type Description
    TypeError

    if event is not a string, if context is neither None nor a mapping with str keys, or if a condition returns an awaitable (a condition is never awaited). Any exception of a handler or a condition also propagates.
    RuntimeError

    if a handler or a condition raises a StopIteration: Python does not let a coroutine raise it. The __cause__ of the error is the StopIteration, which has the note.
    Example 
    >>> import asyncio
>>> from minevent import EventManager
>>> manager = EventManager()
>>> async def hello_handler(context):
...     print(f"Hello {context['name']}!")
...
>>> _ = manager.add_event_handler("my_event", hello_handler)
>>> asyncio.run(manager.atrigger_event("my_event", {"name": "John"}))
Hello John!

    minevent.EventManager.trigger_event ¶

    trigger_event(
    event: str, context: Mapping[str, object] | None = None
) -> None

    Run the handlers of an event, in the order they were added.

    The handlers registered when the trigger starts run one after the other, and a registration removed before its handler is called, even by its own condition, does not run. The condition of a registration is evaluated just before its handler. No handler runs if the event has none. The trigger is fail-fast: an exception of a handler or a condition propagates unwrapped, with a note that says what raised it, and the next handlers are skipped. If one of the registrations has a coroutine function as handler (a callable object is judged by its __call__), the trigger is rejected before any condition or handler runs.

    Parameters:

    Name Type Description Default
    event str

    The event name (case-sensitive string) to trigger.

    		 required
    context Mapping[str, object] | None

    The data of the trigger: a mapping from str to values, a Context or None (no data). A mapping is copied into one read-only Context shared by the handlers and the conditions, and a Context is used as is. Default is None.

    		 None

    Raises:

    Type Description
    TypeError

    if event is not a string, if context is neither None nor a mapping with str keys, if a handler is a coroutine function (nothing runs, use atrigger_event), or if a condition or a handler returns an awaitable. Any exception of a handler or a condition also propagates.
    Example 
    >>> from minevent import EventManager
>>> manager = EventManager()
>>> manager.trigger_event("epoch_end")  # no handler: nothing happens
>>> _ = manager.add_event_handler(
...     "epoch_end", lambda context: print(f"epoch {context['epoch']}")
... )
>>> manager.trigger_event("epoch_end", {"epoch": 3})
epoch 3

    minevent.PeriodicCondition ¶

    Implement a periodic condition.

    This condition evaluates to True on one call in freq, from the call of index start (the first call has the index 0). It maintains an internal counter that increments with each call. The condition is True when the counter minus start is not negative and is a multiple of freq. With freq=3, start=0 is True on the calls 0, 3 and 6, start=3 skips the first call (3, 6 and 9), and start=2 is True at the end of every third call (2, 5 and 8). With freq=1, it is a warm-up: False for the first start calls and True afterwards.

    Note that a call is not idempotent: each call advances the counter, so the condition is stateful. Do not share one instance between several handlers, because they would advance the same counter. The step property reads the counter without advancing it, and reset restarts it.

    The counter is protected by a lock, so every call is counted once, from any number of threads, with and without the GIL. A lock cannot be copied or pickled: a copy of a condition (copy.copy, copy.deepcopy or pickle) starts at the same step, and then has its own counter and lock.

    Parameters:

    Name Type Description Default
    freq int

    The frequency (interval) at which the condition evaluates to True. Must be a positive integer.

    		 required
    start int

    The index, from 0, of the first call that evaluates to True. Must be a non-negative integer. Default is 0.

    		 0

    Raises:

    Type Description
    TypeError

    if freq or start is not an integer.
    ValueError

    if freq is lower than 1, or if start is lower than 0.
    Example 
    >>> from minevent import PeriodicCondition
>>> condition = PeriodicCondition(freq=3)
>>> [condition() for _ in range(7)]
[True, False, False, True, False, False, True]
>>> condition = PeriodicCondition(freq=3, start=2)
>>> [condition() for _ in range(7)]
[False, False, True, False, False, True, False]
>>> condition = PeriodicCondition(freq=1, start=2)
>>> [condition() for _ in range(4)]
[False, False, True, True]
>>> import copy
>>> clone = copy.deepcopy(condition)
>>> clone
PeriodicCondition(freq=1, start=2, step=4)

    minevent.Subscription ¶

    Represent the registration of a handler to an event.

    EventManager.add_event_handler returns a subscription: it is the registration itself, so remove removes that registration only, even if the same handler is registered several times. Subscriptions are compared by identity, and copying or pickling one raises a TypeError. A subscription is a context manager: the registration is removed when the with block exits. Its repr shows the event and the name of the handler, then what else decides whether the handler runs: once=True, the name of the condition and active=False if the registration is not in the manager.

    The constructor is internal: subscriptions are created by the event manager, and one that is built by hand is not active.

    Parameters:

    Name Type Description Default
    manager EventManager

    The event manager that stores the registration.

    		 required
    event str

    The event name of the registration.

    		 required
    handler Handler

    The registered handler (Handler).

    		 required
    once bool

    If True, the handler runs at most once. Default is False.

    		 False
    condition Condition | None

    The condition evaluated before the handler, or None if the handler always runs. Default is None.

    		 None

    Raises:

    Type Description
    TypeError

    if EventManager.add_event_handler rejects handler or condition.
    Example 
    >>> from minevent import EventManager
>>> def print_epoch(context):
...     print(context["epoch"])
...
>>> def is_late(context):
...     return context["epoch"] >= 2
...
>>> manager = EventManager()
>>> subscription = manager.add_event_handler("my_event", lambda: None)
>>> subscription
Subscription(event='my_event', handler='<lambda>')
>>> subscription.remove(), subscription.remove()
(True, False)
>>> subscription.active
False
>>> subscription
Subscription(event='my_event', handler='<lambda>', active=False)
>>> manager.add_event_handler("my_event", print_epoch, once=True, condition=is_late)
Subscription(event='my_event', handler='print_epoch', once=True, condition='is_late')
>>> manager.reset()
>>> with manager.add_event_handler("my_event", lambda: None):
...     manager
...
EventManager(events={'my_event': 1})
>>> manager
EventManager(events={})
